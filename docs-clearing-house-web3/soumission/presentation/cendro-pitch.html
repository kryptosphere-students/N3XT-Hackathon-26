The problem

Who approved this order?

Order by email→ Retyped by a back office→ Settled T+2 or T+3

The proof that a manager approved it sits in an inbox, not in a signature anyone can check.

And now an AI agent reads that inbox. It can be fooled by the very email it reads.

A2 · Why plain text, not EIP-712

We never ask anyone to blind sign.

What we tested, 11 Oct

signTypedData with our own types on the Flex: the device asks to enable blind signing. After refusing, the error is 6a80 Invalid data.

Why

Clear Signing needs an ERC-7730 descriptor in the registry for our types and contracts. A hackathon project does not have one.

What we chose

Every human signature is EIP-191 text, built by one shared function in the browser and rebuilt on the server.

Next

Write ERC-7730 descriptors, then sign approvals as clear-signed typed data and verify them in the escrow.

Cendro appendix
Decision D6, confirmed with the Ledger mentors. The cost of plain text: the escrow cannot parse it, so it trusts the engine key to verify, and the signatures are published for anyone to check.

A3 · The escrow and the lot hash

All or nothing, and the same hash on both sides.

settle(lotId, navPerUnit, positions, navHash, signatures) // engine role only

Reverts if

the lot was already settled, shares or cash do not sum to zero, a balance would go negative, or a participant is not whitelisted.

Emits

LotSettled(lotId, lotHash, navHash, signatures): anyone can re-check the approvals afterwards.

Lot hash

keccak256(abi.encode(lotId, shareToken, cashToken, navPerUnit, positions)), computed by the contract and by the engine.

Tested

A parity test checks the engine against the contract's reference hash. Fuzz tests: any balanced lot settles, any unbalanced lot reverts.

Cendro appendix
Instant mode is not separate code: a lot of one order, two lines, through the same settle. Participants are prefunded in the escrow so nobody signs an approve of a test token, which would be blind signing.

A4 · The NAV

Computed by code, hashed with every lot.

( 60,000 bonds × 101.25 + 4,525,000 cash − 100,000 liabilities ) ÷ 100,000 shares
= 105.000000 per share, rounded down to the cash unit

navHash = keccak256(abi.encode(fundName, navDate, source, holdings, liabilities, sharesOutstanding, navPerUnit))

Source

A mock fund administrator file. The NAV stays a legal act of the administrator; we compute and prove it, we do not decide it.

Audit

The NAV hash is published in LotSettled. Change one input and the hash changes.

Cendro appendix
The code guarantees the arithmetic and the trace, not the accuracy of the prices. A price oracle and an on-chain NAV are on the roadmap.

A5 · The agent's guardrails

The agent can be wrong. It cannot be dangerous.

One tool

draft_instruction: fund, side, units as text, manager. Any other tool call is refused and logged.

No numbers from the model

Units are parsed by our code into exact integers. Prices, cash and totals are never computed by the model.

Code decides

Every draft goes through the mandate check before anything can be signed. A refused draft has no sign button.

Bounded cost

500 tokens per call, a fallback model, and the API key kept encrypted with Ledger Key Ring.

Cendro appendix
If the model is compromised, the worst it can do is propose a draft. The mandate check refuses it, and even a hand-signed out-of-mandate order is stored as rejected and never enters a lot.

A6 · What a pilot needs

From hackathon to a first client.

  • Approvals verified inside the escrow. Done on a branch, not deployed yet.
  • ERC-7730 descriptors, so approvals can be clear-signed typed data.
  • A real NAV feed from the administrator instead of the mock file.
  • A network chosen with the client, with confidentiality between participants.
  • An external audit of the contracts, and interviews with post-trade teams to measure volumes and the real netting rate.
Cendro appendix
Nothing commercial is validated yet: volumes, netting rate, price, and integration cost, which is the main margin risk. A depositary's buying cycle takes months, with a security audit.
